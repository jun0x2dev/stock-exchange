# fds

## 정의

규칙 기반 이상거래 탐지. 주문·체결·로그인 기록을 사후에 훑어 의심 거래를 경보한다. 거래를 막지는 않는다.

## 주요 상태/흐름

```
10초마다 ─▶ 최근 10분의 기록을 규칙으로 검사 ─▶ fds_alert (같은 사건은 한 번) ─▶ 운영 화면 '이상거래 경보'
```

- 주문 처리 경로와 분리한다. 탐지가 느리거나 실패해도 주문과 체결에는 영향이 없다.
- 규칙 하나는 SQL 한 문장이다. 같은 기록을 여러 번 검사해도 `UNIQUE(rule, dedupe_key)` 때문에 경보는 한 번만 남는다. 여러 서버가 동시에 돌려도 같다.
- 경보는 추가만 하고 지우지 않는다. 확인·오탐 처리는 아직 없다.

### 허수성 호가 (SPOOFING)

다음을 모두 만족하는 취소된 주문을 경보한다. 기준값은 **프로젝트 정책**이며 거래소 규정이 아니다(`exchange.fds.spoofing`).

| 조건 | 기준 | 의도 |
|---|---|---|
| 체결 | 10% 이하 | 체결될 생각이 없었다 |
| 수명 | 10초 안에 취소 | 잠깐 보이고 사라진다 |
| 이득 | 주문이 살아 있는 동안 같은 계좌가 반대편에서 체결 | 보이게 한 호가로 반대편에서 거래했다 |
| 비대칭 | 가짜 주문 수량이 그 반대편 체결의 5배 이상 | 보여 준 것이 실제 거래보다 훨씬 크다 |
| 지배력 | 들어온 순간 같은 쪽 호가 잔량의 50% 이상을 혼자 차지 | 호가창 한쪽을 두껍게 보이게 했다 |

- "이득" 조건이 없으면 큰 주문을 냈다가 마음을 바꾼 정상 고객까지 경보한다.
- "비대칭"과 "지배력"이 없으면 시세가 바뀔 때마다 호가를 거두는 시장 조성자(maker 봇)를 경보한다. 첫 실험의 "종목 주문 크기 중앙값의 5배" 기준은 작은 주문이 많으면 중앙값이 낮아져 시장 조성자의 보통 호가도 걸렸다. 실험을 거치며 바꾼 과정은 실험 기록에 있다.

## 실험용 공격자

`exchange.bot.spoofer.enabled=true`이면 `spoofer` 계정이 종목을 돌며 스푸핑(매수·매도)과 미끼(큰 주문만 내고 취소)를 번갈아 한다. 정답을 알 수 있도록 멱등키 앞에 `spoof-`, `gain-`, `decoy-`를 붙인다. 측정 결과는 [실험 기록](../../experiments/2026-11-27-spoofing-detection.md)에 있다.

## 한계

- 최근 10분만 본다. core가 10분 넘게 꺼져 있었으면 그 사이를 놓친다.
- 가짜 주문을 여러 개로 쪼개거나, 반대편 거래를 다른 계좌로 하면 이 규칙으로는 잡지 못한다. 계좌 연결은 통정·가장매매 규칙에서 다룬다.
- 시세 영향(가짜 주문 뒤 가격이 움직였는지)은 보지 않는다.
