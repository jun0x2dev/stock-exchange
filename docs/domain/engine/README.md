# engine

## 정의

- `matching`: 호가창, 매칭 규칙, 명령 처리. DB, Spring, Kafka에 의존하지 않는 순수 Java이며 시계와 난수를 쓰지 않는다.
- `exchange-engine`: 명령 토픽을 읽어 `matching`으로 처리하고 결과를 내보내는 프로세스. DB에 접근하지 않는다.

## 주요 상태/흐름

- `PLACE` → `Accepted` 다음에 `Traded`가 0개 이상, 자전거래면 `Canceled`로 끝난다. `CANCEL` → `Canceled`, 이미 빠진 주문이면 결과가 없다.
- 모든 이벤트에 종목별 순번을 붙이며, 접수 순번이 시간 우선의 기준이 된다.
- 결과와 읽은 위치를 한 Kafka 트랜잭션으로 커밋한다. 시작하면 명령을 처음부터 다시 처리하되 커밋한 위치까지는 결과를 내보내지 않는다.
- 같은 명령은 명령 ID로 한 번만 처리한다(종목별 최근 10,000건).
- 엔진이 두 개 떠도 `transactional.id`가 같아 나중에 뜬 하나만 결과를 낼 수 있다.

## 관련 불변식

- 같은 명령 기록에는 같은 이벤트와 호가창이 나온다. 매수 호가는 항상 매도 호가보다 낮다.
- 무작위 명령(`OrderBookTest` 2만 건 × 시드 5개, `CommandProcessorTest` 중복을 섞은 5천 건 × 시드 3개)과, 다시 처리한 호가창을 DB 주문과 비교하는 통합 테스트로 검증한다.

## 관련 이벤트 (Kafka 토픽)

`order-command` 소비, `engine-event` 발행

## 한계

- 시작할 때 명령 전체를 다시 처리하므로 기록이 쌓일수록 느려진다. 스냅샷은 3단계다.
- 브로커가 하나이고 Kafka는 기본적으로 디스크 동기화를 기다리지 않는다. 전원이 나가 Kafka 기록을 잃으면 DB와 어긋나며, 이때는 종목을 멈춘다.
