# adjustment

## 정의

잘못된 입금·입고를 반대 전표로 되돌리는 원장 정정. 원래 기록은 고치거나 지우지 않는다.

## 주요 상태/흐름

```
REQUESTED ──(승인)──▶ APPROVED   반대 전표 기록, 잔고 차감
    └──────(거절)──▶ REJECTED   같은 전표를 다시 요청할 수 있음
```

- 운영 화면(`/admin`)에서 운영자는 최근 입금·입고 목록에서 고르고, 승인자는 사유와 요청자를 확인한 뒤 결정한다. 화면은 역할에 맞는 버튼만 보여 줄 뿐이고 권한은 서버가 검사한다.
- 운영자(OPERATOR)가 요청하고 승인자(APPROVER)가 결정한다. 역할, 서비스, DB `CHECK (decided_by <> requested_by)`가 각각 자기 승인을 막는다.
- 애플리케이션 DB 계정은 사용자의 역할을 바꿀 수 없어, 앱을 통해 운영자를 승인자로 바꿀 수도 없다.
- 전표마다 진행 중이거나 승인된 요청은 하나다(부분 유일 인덱스). 이 제약이 멱등키를 대신한다.
- 승인과 반대 전표는 한 트랜잭션이다. 되돌릴 잔고가 부족하면 승인까지 롤백되어 대기 상태로 남는다.

## 관련 불변식

I1~I4. 반대 전표도 상대 계정(`EXTERNAL`)과 합이 0이다.

## 한계

- 되돌릴 수 있는 것은 입금과 입고뿐이다. 체결의 정정은 다루지 않는다.
- 고객 계정과 직원 계정의 실제 사용자가 같은지는 알 수 없다.
