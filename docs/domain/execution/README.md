# execution

## 정의

엔진 결과를 주문, 잔고, 보유 종목, 원장에 반영하고 체결을 조회한다.

## 주요 상태/흐름

- 잠금 순서: 계좌(ID 순) → 보유 종목(계좌 ID 순) → 주문(ID 순).
- 결과를 최대 20개씩 한 트랜잭션으로 반영하고, 실패하면 하나씩 다시 시도한다([이유](../../trade-offs/2026-11-24-batch-settlement.md)).
- DB에 커밋한 뒤 Kafka 위치를 커밋하므로 같은 결과가 다시 올 수 있다.

| 받은 결과의 순번 | 처리 |
|---|---|
| `last_event_seq` 다음 | 반영 |
| `last_event_seq` 이하, 같은 주문이 같은 순번으로 반영돼 있음 | 중복이므로 버림 |
| `last_event_seq` 이하, 반영 내용이 다름 | Kafka 기록이 바뀐 것이므로 종목 정지 |
| 순번이 빔 | 종목 정지, 처음부터 다시 읽을 위치 기록 |
| 반영이 3번 연속 실패 | 종목 정지, 실패한 위치 기록 |

- 정지는 종목 단위다. 같은 파티션의 다른 종목은 계속 처리한다.
- 다시 열기: 원인을 없애고 종목을 `TRADABLE`로 바꾼 뒤 core를 재시작하면 기록한 위치부터 다시 읽는다. 다른 종목의 결과는 중복으로 버려진다.

## 관련 불변식

I1~I7 전부.

## 관련 이벤트 (Kafka 토픽)

`engine-event` (키: 종목, 보존 기간 없음)
