# reconciliation

## 정의

잔고와 원장, 주문과 체결, 감사 로그가 서로 맞는지 매일 확인하고 결과를 남기는 대사.

## 주요 상태/흐름

```
1시간마다 확인 ─▶ 전날 정기 대사가 없으면 실행 ─▶ PASSED / FAILED 기록
운영자·감사 담당자 ─▶ 지금 대사하기 ─▶ MANUAL로 기록
```

- 불변식 I1~I7은 테스트와 같은 뷰(`invariant_violation`)로 검사하고, 감사 로그는 해시 체인을 처음부터 다시 계산한다.
- 불변식 검사와 결과 저장은 한 SQL 문장이다. 체결이 반영되는 중에도 한 시점의 잔고와 원장을 비교한다.
- 정기 대사는 날짜(한국 시간, DB 시계)마다 한 번만 기록된다. 유일 인덱스와 잠금으로 막아 여러 서버가 동시에 실행해도 같다. 그 시각에 꺼져 있었으면 켜진 뒤 1시간 안에 따라잡는다.
- 대사는 한 번에 하나만 실행한다. 겹친 수동 실행은 409로 거부한다.
- 실행 이력과 불일치 내역은 추가만 한다(5년 보존 대상). 불일치는 1,000건까지 저장하고 건수는 모두 센다.
- 불일치가 있으면 ERROR 로그를 남기고 운영 화면 맨 위에 경고를 띄운다.

## 관련 불변식

I1~I7 전부와 감사 로그 무결성.

## 한계

- 실행한 시점의 상태를 본다. 불변식은 언제나 참이어야 하므로 특정 시각 기준의 재계산은 하지 않는다.
- 원장 전체를 합산한다. 데이터가 커지면 날짜별 합계를 남기고 그 이후만 더하는 방식으로 바꾼다.
- 알림은 로그와 화면뿐이다. 메신저·메일은 배포하지 않는 이 프로젝트에서는 붙이지 않았다.
