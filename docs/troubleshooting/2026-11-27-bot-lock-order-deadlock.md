# 호가 봇과 체결 반영의 교착

## 증상

이상거래 탐지 실험(봇·시세·공격자 10분)에서 `deadlock detected`가 3번 났다. 한쪽은 봇의 호가 접수(`UPDATE account ... reserved_cash`), 다른 쪽은 체결 반영(`INSERT INTO position ... ON CONFLICT`)이었다. 두 번은 체결 반영이 져서 롤백됐고 재시도로 회복했다. 불변식 위반과 종목 정지는 없었지만, 재시도를 소진하면 종목이 `HALTED`된다.

## 원인

봇은 한 트랜잭션에서 호가 여러 개를 낸다. 매수 예약은 계좌 행을, 매도 예약은 보유 종목 행을 잠그는데 매수·매도를 번갈아 내서 **보유 종목 → 계좌** 순서가 생겼다. 체결 반영은 정해진 대로 **계좌 → 보유 종목** 순서로 잠근다. 사용자 주문은 한 번에 하나라 문제가 없었고, 3단계에서 봇을 넣을 때 이 규칙을 확인하지 않았다.

## 해결

- 봇이 한 트랜잭션에서는 매수를 모두 낸 뒤 매도를 내게 했다. 잠금 순서가 체결 반영과 같아진다.
- `QuoteBotTest`가 접수 순서(매수 3개 → 매도 3개)를 검사한다. 수정 전 코드에서는 실패한다.
- 수정 뒤 같은 조건으로 10분 실험을 다시 돌려 교착이 나지 않는 것을 확인했다([실험 기록](../experiments/2026-11-27-spoofing-detection.md)).
