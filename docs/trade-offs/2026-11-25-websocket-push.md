# 실시간 화면에 무엇을 보낼 것인가

## 선택지

1. 바뀌었다는 알림만 보내고 화면이 전부 다시 조회한다.
2. 호가·체결은 내용을 보내고, 내 주문·잔고는 알림만 보낸다.
3. 내 주문·잔고까지 모두 내용을 보낸다.

## 선택

2번. Spring의 기본 WebSocket을 쓰고 STOMP 같은 메시지 프로토콜은 쓰지 않는다.

## 이유

- 호가와 체결은 모두에게 같은 내용이고 자주 바뀌므로 한 번 만들어 여러 화면에 보낸다.
- 내 주문과 잔고를 보내려면 소유자 검증을 WebSocket 쪽에 한 번 더 만들어야 한다. 알림만 보내면 이미 검증된 API 하나로 끝난다.
- 구독은 종목 하나뿐이라 주소로 충분하다.
- 감수한 점: 알림을 받을 때마다 조회가 몇 번 일어난다.
