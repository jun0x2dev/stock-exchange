# 프론트엔드 기술과 저장소 구조

## 선택지

- 화면 기술: React + Vite / Next.js / Vue / Thymeleaf
- 저장소: 한 저장소에서 폴더 분리 / 저장소 분리 / 백엔드 안에 포함

## 선택

React + Vite + TypeScript를 쓰고, 한 저장소에서 `backend/`와 `frontend/`로 나눈다. 두 쪽은 같은 출처로 서비스한다.

## 이유

- 로그인 뒤에 쓰는 거래 화면이라 SSR과 검색 노출의 이점이 작다. Next.js는 Node 서버와 인증 경계가 하나 더 생긴다.
- Thymeleaf는 단순하지만 자주 바뀌는 호가창에는 결국 별도 스크립트가 많이 필요하다.
- React와 TanStack Query, WebSocket 조합은 증권사 웹 트레이딩(WTS) 공개 채용 공고에서도 확인되어, 비슷한 화면에 쓰이는 검증된 조합으로 판단했다. 점유율 통계는 찾지 못했다.
- 세션 쿠키와 CSRF 방어를 쓰므로 같은 출처가 단순하고 안전하다. CORS를 열 필요가 없다.
- 한 저장소면 API와 화면 변경을 한 번에 검토할 수 있다. 폴더를 나눈 것이며 MSA는 아니다.
- 감수한 점: 빌드 도구가 두 가지가 되고, CI에 프론트엔드 작업을 따로 추가해야 한다.
