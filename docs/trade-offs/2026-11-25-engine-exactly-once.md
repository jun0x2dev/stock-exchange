# 엔진의 중복·누락 방지: Kafka 트랜잭션과 전체 재처리

## 선택지

1. 결과를 최소 한 번 발행하고, 재시작하면 모든 결과를 다시 발행해 core가 중복을 버린다.
2. 결과와 읽은 위치를 Kafka 트랜잭션으로 함께 커밋하고, 커밋한 위치까지는 결과를 다시 내보내지 않는다.
3. 엔진이 호가창을 DB에 저장한다.

## 선택

2번. core의 순번 검사는 그대로 유지한다.

## 이유

- 1번은 재시작할 때마다 지금까지의 모든 결과가 다시 나가 core가 매번 전부 확인해야 한다.
- 3번은 엔진이 DB에 묶여 분리한 의미가 없고, 매칭이 디스크 동기화를 기다리게 된다.
- `transactional.id`가 같으면 이전 엔진이 차단되므로, 멈춘 줄 알았던 엔진이 되살아나 결과를 두 번 내는 일도 막는다.
- core의 순번 검사를 없애지 않은 이유: core는 DB 커밋 뒤 Kafka 위치를 커밋하므로 중복을 받을 수 있고, 순번이 비는 것을 알아채는 유일한 방법이다.
- 발행기도 Kafka 트랜잭션을 쓴다. 묶음이 일부만 나가면 다시 보낼 때 취소가 접수보다 먼저 도착할 수 있다.
- 감수한 점: 1단계의 주문은 명령 기록이 없어 이어받지 못한다. 빈 DB에서 시작하며 V5 마이그레이션이 이를 강제한다. DB와 Kafka 볼륨은 항상 함께 지워야 한다.
