# 일 단위 대사를 어떻게 돌릴 것인가

## 선택지

1. 자정에 한 번 실행하는 cron.
2. Spring Batch 같은 배치 프레임워크.
3. 1시간마다 "전날 정기 대사가 있는가"를 확인하고 없으면 실행한다. 날짜마다 한 번은 DB 유일 인덱스로 보장한다.

## 선택

3번. 결과는 불변식 뷰를 읽는 SQL 한 문장으로 실행 이력과 불일치 내역에 함께 저장한다.

## 이유

- 1번은 자정에 꺼져 있던 날을 조용히 건너뛴다. 로컬 PC에서 도는 이 프로젝트에서는 흔한 일이다.
- 2번은 단계 하나짜리 작업에 테이블과 설정이 많이 늘어난다. 재실행 안전성은 유일 인덱스와 잠금으로 충분하다.
- 검사와 저장을 한 문장으로 하면 "실행했는데 기록이 없다"거나 "검사한 시점과 저장한 내용이 다르다"는 경우가 생기지 않는다. 기록을 나중에 고치지 않아 추가 권한만으로 된다.
- 감수한 점: 원장 전체를 매번 합산한다. 불일치 알림은 로그와 화면뿐이다.
